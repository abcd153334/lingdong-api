# 定价怎么写

平台内部只有一个金额单位：**微**。`1 结算货币单位 = 1000000 微`。

- ¥7.20 / 百万 tokens → `input_price: 7200000`
- ¥0.05 / 张 → `tier_price: {"1K": 50000}`
- 免费 → `0`

**没有倍率、没有刻度、没有"1 元兑多少额度"这层换算。** 你填的微就是用户被扣的钱。
币种见 `schema_get(section=plan)` 的 `pricing_currency`（站点锁定一种，不能按模型指定）。

填之前先心算一遍：把微除以 1000000 得到金额，看它是不是运营说的那个数。
差 100 倍、100 万倍的提案一律是单位写错，必须改到对为止 —— 这类错上线后
表现为"某个模型一次对话扣了 7 块钱"，是资金事故而不是配置问题。

## 三种计费方式（`billing_mode`）

- `tokens` 按量：按 token 计费。必填 `input_price`，可选 `output_price` 与缓存/图像/音频 lane
- `call` 按次：每次调用固定价。必填 `call_price`
- `spec` 按规格：按张/按秒/按档位。必填 `spec_prices`

模态决定可用计费方式（见 `schema_get(all).modalities`）：图像/视频/音乐只能 `spec`；
音频可以 `call`（固定价）或 `spec` + `kind=per_second`（按秒）。

**音频什么时候用按秒**：上游按"生成时长"收费（文档写「¥x/秒」「按秒计费」「最低 x 秒」）时必须用
`per_second` —— 用 `call` 会让 5 秒广告语和 10 分钟有声书同价，长短混用必然一边亏。
按秒的前提是**时长有真实来源**：桥接的 `extract.duration`，或平台从音频头（WAV/FLAC/MP3）探测。
两者都没有时平台只能按最低消费收并记 anomaly，这时应改用 `call`。

写之前先 `schema_get(section="spec_prices")` 确认字段名与档位键。

**价格本身查不到**：`schema_get` 只给字段名与档位键，库里没有"这家多少钱"。
文档写了就照文档；文档没写、只写"按调用计费"、或只给了一个没标币种的数字 →
必须 `ask_user` 问运营（见 05-when-to-ask）。猜价格等于猜对账。

## 写价之前查什么

- 按量的 8 条 lane（`input_price` / `output_price` / `cache_price` / `cache_create_price` /
  `cache_create_price_1h` / `image_price` / `audio_price` / `audio_output_price`）的字段名、
  含义与"哪条必须给"：`schema_get(section="plan", entity="model")`。
- 按规格的价目字段、档位键（`1K`/`2K`/`4K`、`480p`/`720p`/`1080p`/`2k`）、各字段上限：
  `schema_get(section="spec_prices")`。
- **不要照抄任何文档里的键名**：键名写错不会被归一化纠正，运行期命中不到 →
  静默回落默认价（没有默认价则直接拒绝）。

## 判据：会被拒 / 会静默出错

1. 负价一律拒绝。负的输出价会让输出 token 变成"退款"。
2. `input_price = 0` 时其它 lane 必须也是 `0`，否则账单无法解释。
3. 更新时**省略 = 沿用库内现值**；显式写 `0` 才是"免费"。这两个语义完全不同：
   想清零却省略了，结果就是"没改"。
4. 音频按秒：`kind` 必须是 `per_second` 并给 `per_second_price`（微/秒）。
   上游有最低计费时长就必须给 `min_price`（"最低按 10 秒收" → 10000 微 = ¥0.01），
   否则短文本会系统性少收。`max_seconds` 是防御异常时长的封顶，可选。
5. 视频档位**没有 4k**；音频不要用 `second_price`（那是视频的档位表）。
6. 参考素材"按条"与"按秒"**互斥**，同时非空会被拒。
7. 超时溢价两个字段必须**成对**出现，倍率用微比例（1.5 倍 = `1500000`）。
8. 按量模型漏给 `input_price`、音频按秒漏给 `min_price`、把"元"当"微"填
   （¥7.2 写成 `7` → 实际白送）—— 这三类是最常见的静默错误，提交前逐条对一遍。

## `is_free`

派生字段，由价格数值唯一决定（已配置的价格全为 0 = 免费；一个都没配 ≠ 免费）。
**不要写**，写了会被拒绝。

## 常见错误

- 音频按秒写了 `second_price`（那是视频的档位表，音频用 `per_second_price`）
- 音频按秒没写 `min_price`，而上游有最低计费时长 → 短文本系统性少收
- 视频模型写 `4k`
- 半免费：输入 0、输出 1.5
- 按量模型漏了 `input_price`
- 把 `call_price` 填到按量模型上（字段会被严格解析拦下）
- 把"元"当"微"填（¥7.2 写成 `7` → 实际 0.000007 元/百万 tokens，等于白送）
- 用了带 `_quota` 后缀的旧键名（`resolution_prices_quota` 之类）—— 会被严格解析直接拒绝

## 分组折扣（不在模型上）

模型价目是**平台基准价**；用户实付 = 基准价 × 分组折扣。
折扣只存在于 `group_discounts`（键 = 渠道的 `groups` 里的分组名），单位是**微比例**：
`1000000` = 不打折、`900000` = 九折、`1500000` = 加价 50%。

所以：**不要在模型上找折扣字段**（没有），也不要把折扣写进 `prices`（那是基准价，
写进去等于给所有人降价且再也算不出原价）。分组归属属于"必须问"的范畴（见 05-when-to-ask）。

## 切换计费方式会清空另一套价目

`billing_mode` 决定用 `prices` 还是 `spec_prices`，平台只落一套：
把 `spec` 改成 `tokens`，旧 `spec_prices` 会被显式清成 NULL；反过来一样。
这是刻意的 —— 两套价目同时存在时，"这个模型到底按什么收钱"就没有唯一答案了。

后果：改计费方式的那一次提案**必须同时给新价目**，否则模型会处于"已启用但没价"的状态，
运行期直接拒绝调用，表现是「这个模型突然不能用了」。

## 结算期的两条硬规则

- **预扣严格、结算饱和**：预扣阶段超过上限直接拒绝（400），结算阶段超过上限
  按上限收费并打 anomaly 标记（`image_n_capped` 等）。所以"按上限封顶"只发生在结算，
  不要在提案里指望它兜住预扣。
- **时长/张数拿不到真实值**：按秒计费的音频若既没有上游时长、也探测不到音频头，
  平台会按文本估算秒数并打 `audio_seconds_estimated`；连文本都没有才按最低消费收
  （`audio_seconds_unknown`）。看到这两个标记说明该渠道的时长来源缺失，应补 `extract.duration`。
