# 何时该问运营

工具是 `ask_user`：问出去之后**原地等回答**（最多 60 秒），答完同一轮继续做。
所以"问一句"不是失败，也不是结束 —— 它是补齐事实的正常一步。

## 三条必须问的判据

只要命中任一条，就不要自己假设：

1. **钱**。计费方式（按量/按次/按规格）与具体单价。文档只写"按调用计费"、
   或写"$0.02/次"但没说是美元还是人民币，都要问。猜错价格 = 猜错账。
2. **密钥与地址**。文档给的是通用地址（`https://api.example.com`），而实际调用
   需要专属域名、区域、账号 ID —— 这些只存在于运营脑子里，文档抄不到。
3. **商业归属**。新供应商分组 `vendor` 叫什么、挂哪个分组、用哪个分组折扣（微比例，1e6 = 不打折）。
   这决定门户上的供应商名与折扣，模型无从判断。

另外一类是**取舍**：两种做法都能跑，但代价不同（原样透传 vs 字段重建、
按次 vs 按规格）。给出选项与代价，让运营选。

## 四条不许问

这些你自己查得到，问了就是浪费一次 60 秒：

- 端点键、模态、计费方式的对应关系 → `schema_get(section="all")`
- 规格 DSL 的字段、取值、上限 → `schema_get(section="spec_dsl")`
- 提案实体与字段 → `schema_get(section="plan")`
- 现有渠道/模型/供应商分组长什么样 → `channel_list` / `model_list` / `vendor_list`

## 怎么问

- **一次只问一件事**。把三个问题塞进一个 `question`，运营只能挑一个答。
- **选项要具体**，2–5 个，每个带代价：`{"value":"per_call","label":"按次计费","detail":"每次 0.02，视频越长越亏"}`。
- `why` 写清楚"缺了它会怎样"，运营据此判断优先级。
- 允许补充文字（默认开）：选项覆盖不到时运营会直接写。

## 问完之后

- 答了 → 按答案继续，**不要重复问同一件事**。
- 跳过 / 超时 / 次数用完（单轮最多 2 次）→ 按**最保守**的默认继续，
  并把这条假设写进最终答复的「未验证项」。不要因为没答案就停在这里，
  也不要悄悄按最贵的方案配。

## 反例

- ❌ 直接编一个 `billing_mode: "call"`，理由是"视频一般按次" —— 应该问。
- ❌ 问"请提供这个供应商的全部接入信息" —— 太宽，运营不知道从哪答起。
- ❌ 问"端点键有哪些" —— `schema_get(endpoints)` 就有。
- ❌ 连续问 3 次以上 —— 第 3 次会被网关拒绝（`status: denied`），
  说明该自己决策了。
